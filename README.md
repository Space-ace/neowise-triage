# Тестовое Neowise. AI-помощник для входящих заявок

## Выполненное решение

Запуск из каталога проекта (Node.js 20+; внешние зависимости не нужны):

```sh
node server.mjs
```

Открыть http://127.0.0.1:3000.

Тесты:

```sh
node --test triage.test.mjs
```

- `server.mjs`: битый JSON и отсутствующий, пустой или нестроковый `text` возвращают 400 `invalid_input`. Ввод обрезается по краям.
- Ответ модели проходит JSON-разбор, проверку допустимой темы и непустого строкового черновика. В HTTP-ответ попадают только проверенные поля, дополнительные поля модели игнорируются.
- Ожидание модели ограничено 300 мс через таймер и `Promise.race`; дополнительно передаётся AbortSignal. Даже провайдер, игнорирующий отмену, не задерживает ответ API. Ошибка или невалидный результат дают 200 `manual_review` с `topic: null`, `draft: null` — по контракту задания.
- `client.mjs`: понятные сообщения вместо сырого JSON, очистка предыдущего результата, сохранение исходного текста в поле, обработка сетевых ошибок и таймаут запроса 5 секунд. Обновлять экран может только последний запущенный запрос; предыдущий дополнительно отменяется. Текст выводится через `textContent`, без интерпретации HTML.
- `mock-ai.mjs` оставлен без изменений.

Пять исполнимых тестов проверяют HTTP-контракт (включая все пять меток имитатора), таймаут при игнорировании AbortSignal, схему результата, очистку старого черновика при сбоях, обратный порядок ответов и запоздалые ошибки. UI-тесты вызывают реальный обработчик страницы с минимальными заглушками DOM и управляемым fetch; это не браузерные E2E-тесты.

Для ручной проверки: сначала введите «Стоимость доставки», затем по очереди `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`. Вместо прежнего черновика должна появиться надпись о ручном разборе. Ввод из пробелов должен показать просьбу ввести текст.

Польза: менеджер получает тему и черновик, а при сбое видит необходимость ручной обработки и не использует старый ответ. Измерять можно время на заявку с учётом проверки и долю черновиков, которые приходится исправлять.

AI: реализация и тесты подготовлены с помощью Codex. Автоматические проверки выполнены агентом; личную проверку кандидата и браузерную проверку это не подменяет. Реальный AI-провайдер не подключался, использован выданный имитатор. Данные хранятся только в поле открытой страницы; постоянного хранения и отправки сообщений клиентам в задании нет.

Ниже сохранено исходное задание.

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

## Что прислать в бота

- Ссылку на pull request и SHA проверяемого коммита. Можно использовать свой учебный репозиторий. Сохраните начальный код первым коммитом, затем откройте PR из отдельной ветки.
- Короткую инструкцию запуска и прогона теста. В описании PR ответьте, где проверяется результат AI, что происходит при сбое, какой AI вы использовали и что проверили самостоятельно. Если работали без AI, укажите это.
- Одну фразу о том, какую пользу задача даёт менеджеру и как её можно измерить.

После сдачи бот может задать один-два коротких вопроса по вашему коду. Используйте учебные данные. Если не уложились по времени, отметьте незавершённые части в PR.
